## Git 提交规范

### 提交信息格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

### 类型 (type)
- feat: 新功能
- fix: 修复
- docs: 文档更改
- style: 代码格式
- refactor: 重构
- test: 测试
- chore: 构建过程或辅助工具的变动

### 范围 (scope)
- core: 核心功能
- ui: 界面相关
- api: API 相关
- docs: 文档
- deps: 依赖
- config: 配置

### 示例
```
feat(api): 添加脚本执行接口

- 实现基础的脚本执行功能
- 添加错误处理
- 集成日志系统

Closes #123
```

## 分支策略

### 主要分支
- main: 主分支，保持稳定
- develop: 开发分支
- feature/*: 功能分支
- bugfix/*: 修复分支
- release/*: 发布分支

### 工作流程
1. 从 develop 创建功能分支
2. 开发完成后提交 PR
3. 代码审查通过后合并
4. 定期将 develop 合并到 main

---

## 发布流程

1. 版本准备
   - 更新版本号
   - 更新更改日志
   - 更新文档

2. 测试验证
   - 运行所有测试
   - 进行集成测试
   - 验证功能完整性

3. 发布步骤
   - 创建发布分支
   - 执行构建
   - 标记版本
   - 合并到 main

4. 发布后
   - 部署新版本
   - 监控系统状态
   - 收集用户反馈
